# 目的地发现与顺路性筛选

本文件用于 Step 2-3。它定义国家级输入、自定义目的地输入和路线覆盖检查的统一口径。

## 1. 先判断输入范围

| 用户输入 | 工作范围 | 处理方式 |
|---|---|---|
| 国家/地区名称 | 全国候选池 | 先搜索主要城市、岛屿、自然目的地，再筛选路线 |
| 一个国内城市/景区 | 指定区域 | 只围绕该目的地规划，可提示邻近候选但不擅自扩展 |
| 多个国内城市/景区 | 自定义组合 | 全部纳入候选池，再判断是否顺路、是否拆分成多条路线 |
| 国家 + 明确城市/岛屿 | 用户指定范围优先 | 国家只用于数据源、签证和交通背景，不自动扩展全国 |
| 入境/离境机场或口岸 | 交通约束 | 只决定起点、终点和可行交通，不决定旅行范围 |

如果用户使用了可能存在多个译名、俗称或错别字的地点名，先保留原始输入，再列出候选对应名称并标记“待确认”；不得在未确认时静默替换成另一个岛屿或城市。

## 2. 国家级候选池最低字段

每个候选目的地至少记录：

```text
目的地中文名
目的地英文名
国家/区域
类型：城市 / 岛屿 / 海滨 / 山区 / 文化遗产 / 自然保护区
核心体验
建议停留天数
最佳季节与本次月份适配度
最近主要机场/港口/车站
与其他候选目的地的主要交通方式和耗时
交通季节性风险
预算档次适配
住宿/餐厅/景点数据可获得性
来源和最后核验时间
```

国家级输入通常先形成 8-16 个候选；候选数量不是越多越好。目的地少、面积小或信息不足时，应说明实际覆盖边界，不要用重复的小区域凑数。

## 3. 顺路性评分

路线比较时使用定性或半定量评分，不得只按“热门程度”排序：

| 维度 | 高分条件 | 低分条件 |
|---|---|---|
| 地理连续性 | 相邻区域、单向推进、可形成环线 | 大幅折返、跨国或跨海跳跃 |
| 交通效率 | 直达、班次稳定、耗时占比低 | 多次换乘、船班不稳定、夜间抵达 |
| 季节适配 | 本月适合主要体验 | 雨季封闭、海况不稳定、活动受限 |
| 停留价值 | 2-4天能形成完整体验 | 只适合半天却需要长途移动 |
| 口岸兼容 | 靠近入境/离境方向 | 需要额外回到原口岸 |
| 数据质量 | 点位和坐标可独立验证 | 只有转载内容或营业状态不明 |

如果某目的地热门但明显绕路，应保留在候选池并标记为“候选但排除”，说明绕行距离、额外交通天数或季节风险。

## 4. 覆盖检查输出

路线确定前必须生成一张覆盖表：

| 目的地 | 状态 | 是否进路线 | 原因 | 后续动作 |
|---|---|---:|---|---|
| 已纳入 | 正式纳入 | 是 | 与主线顺路、停留价值高 | 收集 POI |
| 候选但排除 | 排除 | 否 | 绕行成本过高/季节不合适/交通不稳 | 写入攻略备选 |
| 待验证 | 暂缓 | 未定 | 关键交通或营业状态未确认 | 补查证据 |

不得出现“搜索过但没有出现在候选池、路线或排除表”的目的地。

## 5. 印尼案例的前向测试关注点

当用户输入“印度尼西亚”、给出巴厘岛往返口岸时，候选池至少应主动检查：巴厘岛、日惹、泗水、雅加达、龙目岛、吉利群岛、蓝梦岛、佩尼达岛、科莫多/拉布汉巴焦等；用户额外输入的“金银岛”等可能存在别名的地点必须先进入“待确认”项，不能自行映射为吉利群岛或其他目的地。还应根据实际季节、航班/船班和 14 天限制决定纳入或排除。

巴厘岛往返只表示路线最终回到巴厘岛，不表示其他目的地自动排除。若日惹、泗水或雅加达因航班连接、绕行或停留时间不足而排除，必须在覆盖表中写明原因。
