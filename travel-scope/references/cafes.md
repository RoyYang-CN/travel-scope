# Café collection — both domestic and international

After destination discovery, search cafés for each destination alongside food research. Read `cafe-policy.json` for search terms. Use the existing Amap search/enrichment for mainland China; for overseas destinations use the offline/open-data place resolver declared in `references/map-link-policy.md` and `references/evidence-policy.md` (no Google Places, Geocoding or Maps JavaScript API, no API key, no Google Maps scraping — §17.1). Preserve the existing optional Baidu policy. Add local-language queries where useful. No fixed quota and no mandatory daily café stop.

Determine primary business role using open-data categories and official/menu evidence. A restaurant offering coffee remains a restaurant even when its name contains Cafe. A café, coffee-focused bakery or tea/coffee space may be included independently. Hotel/scenic-site cafés need a distinct, verified POI and travel value. Do not duplicate the same provider ID across restaurants and cafés. Ambiguous candidates stay in research with a reason.

Write `cafes` explicitly, including `[]` when there are no reliable results. Rows use the restaurant schema (11 base fields, provider fields through index 25); do not insert new fields into positional rows. Record addresses, prices, ratings, image sources and identity through existing fields/evidence records. Overseas images use the open-licence media collector (`scripts/collect_open_media.py`) and must satisfy the media evidence chain; keyed Google Places photo endpoints are not an allowed source. Never reuse another POI's images.

Write `cafe_coverage` with one object per destination: `destination`, `status` (`included` or `no_reliable_results`), `queries` (actual queries), `evidence` (source links or saved response references), and `reason` (required for empty results). Failed source calls (including offline resolver errors, rate limits and unreachable mirrors) and unperformed searches are incomplete, not `no_reliable_results`. Record `SOURCE_ERROR` and `NO_RESULT` as different states. Do not manufacture records to pass QA.

Write `cafe_classification` keyed by original POI name: `primary_role` (`cafe` or `restaurant`) and `evidence`. Include decisions for café candidates retained as restaurants as well. Move a verified café into `cafes` upstream and update any itinerary category to `咖啡馆`, preserving its name, coordinates, provider identity and images. No keyword-only automatic migration.

Load these fields with the standard payload loader. Builders assigning globals must also assign `CAFE_COVERAGE` and `CAFE_CLASSIFICATION`. Before formal generation, the shared contract requires coverage for both branches. HTML/MD/Excel hide empty categories. English café descriptions must be supplied in English or supported by explicit translation mappings; Chinese original names remain for wayfinding.
