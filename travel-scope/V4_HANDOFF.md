## v4.0.2 已固化内容

- Q0-Q8 批量问卷，研究深度与行程节奏拆分；默认 AI 全国路线探索。
- Q3/Q4/Q7/Q8 固定选项不得省略；自由输入项保留格式提示，已知答案直接回填；问卷由 `intake-policy.json` 和 `intake_contract.py` 统一生成与验证。
- 默认中文/英文 Excel、中文/英文 Markdown 和单一双语 HTML。
- 国际 Google/Apple、国内高德/百度的无密钥地图链接。
- 三条真实且不同的路线方案，路线、日程与封面轮播联动。
- 正式数据门禁要求三条路线、连续性 100%、Q0-Q8 留痕、节奏上限、POI 来源全覆盖和深度媒体覆盖；不满足时生成与交付均阻断。
- Q7 四档（精简/标准/深度/超级深度）由外部策略配置控制，并根据城市能级（Tier 1 大都会枢纽 vs Tier 2 走廊卫星城）分别约束候选池、分类别 POI 底线、全案总数、媒体与可审计研究轮次；目的地画像负责表达不同国家的地理、交通、资料可得性与不确定性。
- 地图链接使用“地点名 + 目的地 + 国家”消歧；交通必须链接具体站点、机场、港口或码头，纯坐标或路线名不能作为搜索目标。
- 持续吸顶导航、平滑栏目/路线切换、暖色长页背景和目的地支线结构。
- 预算独立导航；住宿、美食、景点、交通和贴士采用支线组织。
- 大图最多三张、五秒轮播、慢交叉淡化、无暂停按钮。
- POI 阅读行不显示小图、原始经纬度或无信息量的聚合评分提示。
- 无专属支线封面时，可复用已核验的同目的地氛围或地方特色图；不得冒充具体 POI 实景，来源角色保留在数据属性和素材清单。
- 交通班次覆盖航班、铁路、轮渡、巴士、班车和联运，并显式记录有效期与核验状态；未来班次未发布时不得编造。
- 搜索页、聚合页和运营商主页只能发现候选，不能算实体或班次证据；Live 使用 `source_evidence_meta`。
- Q7 深度不仅改变数量：深度与超级深度档要求逐实体独立直达来源及交叉复核记录，并严格考核分类别下限与全案下限。
- Live 使用 `map_targets`；只有精确平台链接、合规 Place ID 或独立核验坐标可以通过，搜索候选和占位 ID 失败。
- 每日日程坐标必须绑定实际 POI 或核验交通端点，禁止整条路线复用一个坐标。
- 媒体采集与视觉复核分离；精确来源 ID、原图 URL、SHA256 和独立 evidence 文件是硬门禁。
- 交付现场复算媒体，旧 PASS 报告或与当前 dataset/manifest 指纹不一致的报告无效。

## 后续智能体执行顺序

1. 完整读取 `SKILL.md`，不要依赖旧对话摘要推断规则。
2. 运行 `python scripts/verify_product.py --skill-root <本目录>`；失败即停止，不得自动重封哈希。
3. 为新目的地创建隔离 run 目录，原始需求原样保存；依次完成全国发现、路线走廊、来源、媒体、统一数据、五类输出和 QA。
4. 运行 `scripts/formal_data_gate.py`；通过后才允许正式生成。交付时必须同时提供媒体审计和浏览器视觉 QA 的 PASS 报告。
4. 所有输出从同一 run-local JSON 生成，不对某一个 HTML 手工补业务内容。
5. 修改正式规则时，同时修改产品源和已安装 Skill；先跑测试与完整性检查，再建立新的不可覆盖发布包。
6. 最终说明实际修改文件、测试结果、仍待核验事实和发布包 SHA-256。

## 当前暂缓或待新实战验证

- 手机临时预览、永久链接和原生分享：用户明确暂缓。
- 未来日期的精确航班、船班、铁路或巴士时刻：必须在运营方发布后重新核验。
- POI 精确实景图：当前阅读层采用文本优先；不要为了填图使用搜索缩略图、社交媒体图或来源不清的商家图片。
- Token 优化：优先复用确定性脚本、结构化证据与门禁报告；集中修改后只做一次最终全链路回归。不得通过跳过研究或 QA 来省 Token。
