Travel-Scope v2.9.1

A configuration-driven workflow for multi-destination travel research and route delivery.

Outputs: HTML, Markdown and Excel · Chinese/English · domestic/international branches · full-route QA.

1. Standard intake

Q0 Scope: country, city, region, scenic area, route or custom destinations Q1 Travel month or exact dates Q2 Number of days Q3 Budget: economy / mid-range / luxury / mixed / custom Q4 Travel mode: self-drive / non-self-drive Q5 Arrival port or city Q6 Departure port or city Q7 Search depth: light / medium / deep / super-deep / custom Q8 Map platform: Google Maps / Amap / Baidu / all Q9 Route options: 3 / 5 / 7 / custom / AI recommendation
Domestic branch: when Q4 is non-self-drive, the workflow must research intercity transport, time, cost and frequency, and place transport nodes into the daily itinerary. If Q4 is missing, it defaults to non-self-drive and records that fallback.

2. Scope before point search

Destination discovery

A country request starts with a nationwide candidate pool. A custom city, region or route stays within the requested scope.

Corridor audit

Known travel corridors are tested for direction, transfer cost, seasonality and route fit before detailed POI collection.

Candidate coverage

Included and excluded destinations are recorded with reasons such as time, season, transport or detour cost.

Regional decomposition

Large destinations are split into practical subregions so a route does not collapse into one city or one point per day.

ImagesTwo usable image URLs are required for formal delivery. Public examples use neutral placeholders rather than redistributing provider images.

4. Route and delivery gates

Every route option is complete. Each route in the selector must contain all travel days. Each normal day should include attractions, food, accommodation and necessary transport nodes; self-drive only changes the domestic transport emphasis.
  • Deduplicate same or nested POIs and reject obvious category errors such as bus stops or management offices as attractions.
  • Keep Chinese name, English name and pinyin/address where useful for international visitors.
  • Generate HTML cards and route view, Markdown narrative and Excel worksheets from the same validated data.
  • Run syntax, schema, source, image, route, language, visual and abnormal-case regression checks before delivery.

5. Demo and Live

Demo

Uses a checked-in fixture, does not call provider APIs, and needs no API key. It is for understanding the output structure.

Live

Uses the user's own provider configuration and the complete SOP. Keys remain local and are never committed to examples or public repositories.
